# Third-party notices

The portal's build chain uses `caniuse-lite`, by Ben Briggs and contributors, a package of the [Browserslist/caniuse-lite](https://github.com/browserslist/caniuse-lite) project, based on the compatibility data from [Can I use](https://github.com/Fyrd/caniuse). The package, including its data and code, is made available under [Creative Commons Attribution 4.0 International](https://creativecommons.org/licenses/by/4.0/). We do not modify the package. The project accepts this non-OSI exception for use in the build; the exact version is in the lockfile and the exception has an expiry date in `scripts/licenses/allowed.json`. The package is not included in the portal's standalone image; anyone who redistributes the package or its data must follow its attribution terms.

Next also installs `@img/sharp-libvips-*` (LGPL-3.0-or-later) as a transitive build dependency. The project chose to **disable Next's image optimization and remove sharp and libvips from the final image**, not to accept their distribution. `next/image`, if it is ever used, delivers images without optimization; `/_next/image` returns 404. The absence of the packages at runtime is checked by the production stack test. That check depends on the directory naming patterns of pnpm and Next; since libvips is the only native module expected in the standalone output, the removal in the Dockerfile and the test also reject any `*.node` binary, which covers a layout change that escapes the names. If the feature or the distribution of the library is re-enabled, a new decision will be needed, along with a check of the license obligations, corresponding sources, notices and replacement before publication.
