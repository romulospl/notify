# Production infrastructure

Step by step in `docs/deploy.md`; overview in `docs/arquitetura.md` (update it when a component or production changes). Decision in ADR 0016: one VPS, no high availability, no provisioning tool.

## VPS path

- `init.sh` (Docker from Docker's repository, Docker settings from `infra/scripts/configure-docker.py`, `.env.production` from `.env.production.example` with secrets generated by `infra/scripts/production-env.py`) and `deploy.sh` (validates `.env.production`, builds and starts `infra/compose/prod.yaml`, installs `stellytics-backup.timer`), both at the repository root.
- `infra/compose/prod.yaml`: Caddy (`infra/caddy/Caddyfile`), portal, `ingest-web`, collector, rollup, Umami, and Debian Postgres with WAL-G (`infra/compose/postgres/Dockerfile`, `stellytics-backup`, `stellytics-restore`) archiving to S3-compatible storage. Images are built from the checkout or taken from `PORTAL_IMAGE` and the other image variables.
- A new service goes into `prod.yaml` and, if public, into the Caddyfile; Umami never.
- The collector and rollup have no published ports: OTLP (HTTP and gRPC) goes out through Caddy on `API_HOST`, port 443, and the collector has a memory cap `COLLECTOR_MEM_LIMIT` (ADR 0012).
- The CI `infra` job validates the Caddyfile and install scripts and runs `infra/compose/test/prod-stack-test.sh` (Caddy routes, ports, an API metric through the public host, encrypted backup and restore with a local S3).
- Dockerfiles need BuildKit (`--mount`, `COPY --chmod`).
- Administration through the tunnel `infra/scripts/admin-tunnel.sh`.
- Mount folders, not files, in containers: a file mounted alone keeps pointing to the old version after a replace-by-rename.

## Monitoring (#15, ADR 0005)

`infra/monitoring/` (Prometheus, blackbox, Alertmanager) on a separate host, configured by `infra/monitoring/configure.sh <env-file>` and started with Docker Compose; tested by the `monitoring` job (`infra/monitoring/test/monitoring-test.sh`).

## Availability, load and handover (#51, #52, #54)

- Load: `docs/relatorios/carga-1m-dia.md` (tool in `services/loadtest/`, which refuses a remote target without `-allow-remote`; measured only on a local machine).
- Availability: `docs/sla.md`. One VPS does not sustain 99.99%; HA was dropped as outside the RFP (ADR 0016, ADR 0009 rejected).
- Handover: `docs/transferencia.md` with `infra/scripts/db-export|db-import|db-fingerprint.sh` (import deletes databases: needs `--yes`, refuses a target with tenants and validates dumps before any `DROP`).

## Runbooks (#53)

`docs/runbooks/` (incidents, backup and restore, secret rotation, Umami upgrade, vulnerabilities), each with a "Not tested" section: nothing was exercised in real production. `WALG_LIBSODIUM_KEY` cannot be rotated.
