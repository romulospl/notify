# Tracking script (`packages/tracker`)

- TypeScript bundled with esbuild into `n.js` (IIFE). Logic in `src/tracker.ts`, entry in `src/index.ts`; scripts in `scripts/` run directly on Node (`.ts`, no build).
- **Published versions are immutable:** `published/vX.Y.Z/n.js` plus the hash in `published/sri.json`, all committed. Changed the code? Bump `version` in `package.json` and run `pnpm --filter @stellytics/tracker release`; it refuses to overwrite an existing version. `test/published.test.ts` fails if a published file changes or the current code does not match the `package.json` version. That includes an esbuild update that changes the output.
- Since v1.1.0 the script requests a challenge at `GET /c` and solves the proof with `crypto.subtle` before sending (HTTPS or `localhost` only); v1.0.0 has no proof and the gateway drops its events.
- The gateway serves `published/` at `/s/`. The script sends `POST /e` to the origin it was loaded from, with `Content-Type: text/plain` (avoids the CORS preflight; the body is JSON) and `credentials: "omit"`.
- From the query string only `utm_*` is sent; the referrer goes without query or fragment.
- **Custom events (#50, ADR 0008):** since v1.2.0, `window.stellytics.event(name, properties?)` sends `name` and `data` in `payload`; the gateway validates again (`relay.validateCustom`) and relays only those two fields. No wallet address, hash or amount. The site dashboard lists them in the **Custom events** card since #50 (ADR 0015). v1.4.0 renamed the global from `window.notify` to `window.stellytics` (v1.0.0–v1.3.0 stay as published).
- **Wallets Kit (ADR 0010):** automatic capture was **not** done (the kit only reports through callbacks in the tenant's module). Since v1.3.0 there is the opt-in adapter `window.stellytics.wallets(kit, KitEventType)`: only `WALLET_SELECTED` and `DISCONNECT`, never `STATE_UPDATED`; the kit handler receives `{eventType, payload}` and the id is in `payload.id`. Since v1.5.0 (ADR 0015) the adapter ignores the `WALLET_SELECTED` that kit 2.x fires inside its own `on` with the wallet remembered in `localStorage`; v1.3.0 and v1.4.0 counted it on every visit. The site dashboard shows wallets in the **Wallet connections** card.
- **Ad blockers (#23):** `pnpm --filter @stellytics/tracker check:adblock [host...]` downloads EasyList, EasyPrivacy, the default uBlock Origin lists and Peter Lowe's list and fails if any blocks `/s/vX.Y.Z/n.js`, `/e` or `/c`. It runs in `.github/workflows/adblock.yml` (PRs touching the script or routes, `main` and daily), outside the `ci` aggregator, because the lists change without code changes. Results and the neutral host recommendation in `packages/tracker/docs/ad-blockers.md`.
- Script names and endpoints must not contain terms blocked by ad blockers (`umami`, `analytics`, `track`, `collect`).
